# デスクトップ版の更新確認

GitHubの[最新リリースAPI](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)を手動確認と自動確認で共用する。公開済みの通常リリースのタグをアプリの `major.minor.build` と数値比較し、現在より新しいときだけ通知する。作品や設定内容は送信しない。確認先とブラウザで開くリリースページはアプリ内の固定URLを使い、ダウンロード・インストール処理は持たない。

## リリースの保持

GitHub Releasesには公開済みの最新版だけを残す。両OSのビルド・監査・配布ファイル確認と正式公開が成功してから、
[公開ワークフロー](../.github/workflows/desktop-release.yml)が[旧リリース整理](../scripts/prune-releases.mjs)を実行する。
最新リリースAPIが今回の版を返し、Windows EXEとmacOS DMGが揃っていることを確認したうえで、公開済みの旧Releaseとその配布ファイルを削除する。
Gitタグとコミット履歴、ビルド途中の下書きは保持する。候補は全ページから取得し、不明な版やより新しい公開版があれば削除を始めない。
各削除の直前にも最新版を確認し、取得・削除の失敗や最新版の切り替わりはエラーとして停止する。

更新確認はインストール済みの版のReleaseや履歴一覧を参照しないため、旧Releaseを削除した後も機能する。
[整理処理のテスト](../scripts/test-prune-releases.mjs)は通常CIとリリース前検証に含め、削除対象・失敗時の保護・公開後の呼び出しを確認する。

## 頻度と保存

- 初期設定は1週間ごと。初回、または最後に成功した確認から7日以上経過した起動時・起動中に確認する。手動確認の成功も起点に含む。
- 起動するたびは起動につき1回。失敗した場合は次回起動、または手動確認で再試行する。
- オフでは自動通信・通知をしない。手動確認は利用できる。
- アプリ終了中に動く常駐処理はない。クイック書き出し専用起動ではバッチ終了後に確認を始める。成功・部分失敗・キャンセル・エラーとも、処理が止まり結果画面になってから対象にする。結果画面のOKは通信完了を待たずに使える。
- 頻度・最終成功日時・最後に通知したバージョンは端末の専用設定に保存する。作品の設定JSON、文書切替、Undoとは独立する。旧版からの更新で設定がなければ週次を使う。不正値や未来の成功日時は初期値へ戻す。

## 通信と通知

通常画面の初期化後に確認し、手動確認と競合したときは実行中のリクエストを共用する。タイムアウトは10秒。オフライン、取得失敗、レート制限は自動確認では表示せず、週次では1時間以上おいて再試行する。失敗を成功日時として保存しない。非表示中は自動確認を控え、復帰・ネットワーク復旧時にも期限を確認する。

新しい版が見つかっても、読み込み・書き出し中、別のダイアログが開いている間、非表示中は通知を待つ。実際に表示した版は保存し、同じ版を自動で繰り返し通知しない。手動確認はこの抑制を無視して結果を表示し、通知済みとして記録する。結果が届く前に手動ダイアログを閉じた場合は通知済みにしない。通信中にオフへ変更された場合、その結果で自動通知しない。
