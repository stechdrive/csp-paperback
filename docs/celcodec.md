# celcodecによるCLIP形式処理

CLIPの形式処理はcelcodec 0.2.0へ集約した。セルや工程の規則、出力計画、UI、履歴、Worker・WASM・フォントの初期化はこのアプリが担当する。

監査済みの配布パッケージを `vendor/celcodec-0.2.0.tgz` に同梱し、package-lockのintegrityで固定する。このリポジトリだけをcloneして `npm ci` でインストールでき、隣接するcelcodec作業ツリーや独立した公開レジストリは必要ない。アプリのビルド・CI・リリースは同じパッケージを使う。ライブラリを更新するときは、その配布許可リスト・空seedの出自・ライセンス・秘密情報・ローカルパスを監査し、パッケージとロックファイルを一緒に更新する。

## 残したアプリ処理

`src/utils/clip`の素材/BINC/timeline入口と単一素材Canvas/効果は薄いアダプターである。parserのアプリ型接続、工程分離、仮想セット、構造フォルダ100%、PSD照合・補完、出力計画はそのまま保持する。

原画素材の選択は `source: original`、crop後の累積予算384 MiB。診断codeを既存の日本語案内とImageResourceErrorへ変換し、PSD併用案内をライブラリへ持ち込まない。Canvas生成と解放は既存の資源管理へ接続する。

## 由来と検証

素材の元画像・マスクoffset、文字cache ID/変形後配置、用紙色の解釈は、celcodecに移した既存ネイティブ回帰で確認する。既存の近似・未対応診断は保持する。入力を直接変更せず、無編集保存と未対象データの保持を区別して検証する。

celcodecの単体画像・パッケージ検証とアプリの単体・ブラウザ検証は別記録である。クレジットは[THIRD_PARTY_NOTICES.md](../public/THIRD_PARTY_NOTICES.md)に保持し、ライブラリ側のdocs/provenance.jsonが参照コミット・ファイルhashを記録する。
