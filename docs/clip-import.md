# CLIP読み込みの実装仕様

## 標準の使い方

書き出したい素材が表示される状態でCLIPを保存して、そのまま開く。
CLIPからアニメーションフォルダ、工程構造、セル指定を読み取り、対応する素材を描画する。
クリスタの描画結果を使いたい場合は、同じCLIPから
［ファイル］→［複製を保存］→［.psd(Photoshopドキュメント)...］でPSDを保存して追加する。
CLIPとPSDは、レイヤーの表示状態を合わせて保存する。

CLIP＋PSDではCLIPのUUID・階層・タイムラインと、PSDの画像・マスク・合成属性を使う。
同時読み込みでも、CLIP単独からのPSD追加でも利用可能。
ネイティブIDを保持するため、PSD追加時もマーク・仮想セル・選択・表示設定を引き継ぐ。
画像属性のUndo履歴だけは切り替え時に破棄する。
PSDを先に開いた場合は、同じベース名のCLIPを追加すると対応付ける。

複数タイムラインはナビゲーター内の選択欄（狭い画面では中央のプレビュー上部）で切り替えられ、CLIP保存時の選択を初期値とする。
切り替え時にセル指定と初期表示を再計算し、手動で操作した目アイコンは保持する。
対応トラックがあるフォルダ内の未使用セルは通常、初期OFFになる。
「兼用カット」では保存時のセル表示状態に従い、未使用セルも出力できる。
トラック未対応のフォルダや解析に失敗したトラックを、未使用セルとして一律に隠さない。

## 独立した作画素材としての扱い

セルタイミングは適用する。2Dカメラフォルダと変形系トラックは識別情報を保持するが、
カメラ・変形アニメーションは描画へ適用しない。保存されている場合は
TimeLineOriginalMipmapを優先し、素材の元画像を取り出す。
これらを使っていること自体のダイアログや警告は出さない。
画像素材レイヤーの静的な配置・回転・拡縮・四隅変形は素材の構成として適用する。
ライトテーブル用の参照画像（`LightTableReferCell`）は作画補助として扱い、
レイヤーツリー・合成・PSD照合から除外する。参照元のセルや描画レイヤーは保持する。

## PSDの照合条件

PSDの寸法、全階層の実名、フォルダ種別、兄弟順を照合してから適用する。
統合PSDや構造の異なるPSD、アニメーションフォルダやセルの対応が曖昧になる
同一階層の同名構造はエラーにする。アニメーションフォルダの直接の子だけをセルとし、
セル内部の通常フォルダ・描画レイヤーには同名を許可する。
セル内部も階層と重なり順を照合し、数字名の内部フォルダを別セルにはしない。
同名の出力フォルダは可視フォルダを優先し、下から順に採番する。
不一致の場合も既存のCLIPプロジェクトは保持する。
構造だけから画像の保存時点は証明できないため、同じ保存状態の組を使用する。
PSD併用時はCLIPのレイヤーカラー・境界線・補正などを追加適用せず、PSDの画像属性へ統一する。

## 実装の分担

内部的には従来のPSD＋XDTS入力との互換性を維持する。
CLIPとXDTSを同時に指定した場合はCLIPのタイムラインを使用する。
ユーザー向けの入力案内はCLIP単独、またはCLIP＋PSDに統一する。

- `utils/clip/parser.ts`、`binc.ts`、`timeline.ts`: SQLiteの構造、UUID、BINC 0100の
  ImageCelName、TimeClip、MotionClipを解析。保存fpsと時間単位から換算する。
  空コマ、表示区間の終端、負のキー、時間移動、隣接する反復区間を扱う。
- `types/timeline.ts`: CLIP/XDTS共通のタイムライン。既存XDTS型は互換用の別名。
- `utils/clip/material.ts`: レイヤーごとに元画像・保存画像・文字情報・塗りを復元。
  ある素材の復元失敗がほかの素材の書き出しを中断させない。
- `engine/material-image.ts`: 保存画像、文字、画像素材の配置をCanvasへ変換。
- `engine/material-effects.ts`、`material-adjustment.ts`、`native-blend.ts`:
  選択されたセルと工程の合成へ効果を適用。別セルの保存合成画像を流用しない。
- `utils/project-loader.ts`: ファイル選択、ドロップ、サンプル、EXEクイック書き出しの共通入口。

CLIPの解析とタイル展開はWorkerで実行し、同梱sql.js WASMを使用する。
CDNへの依存や作品データの送信はない。
ラスタは圧縮タイルのヘッダーを検査してから、データのあるタイルを囲む領域だけにRGBAを展開し、
最後に透明余白を切り詰める。各タイルの展開は1回で、画面外のタイルも圧縮データの検証を省略しない。
初期塗り色が残る画像、既定色と異なる未初期化マスク、画像素材の元画像・ブラシ画像は必要な元寸法を保持する。
ベクターの合成用Float32配列は描画された128pxタイルだけ確保し、最終RGBAは透明でない画素の境界内に生成する。
曲線・押印・筆圧・紙質・乱数・合成順とFloat32への丸めは維持し、読み込み完了後に作業タイルを解放する。
画像寸法と単一処理の作業量を検査する。文書全体の展開画像を足して読み込みを打ち切らず、
素材を必要時に復元し、保持量の増加時はキャッシュを解放する。
全面に描画のある素材や最終出力画像には元寸法相当のメモリが必要となる。
アニメーション／セル／工程コンテナの不透明度100%、アートワークの不透明度、
非表示、マスク、工程名の照合、仮想セルは既存エンジンの規則を使う。

「個別に書き出すフォルダ名」と `_` による対象は、読み込み時にフォルダ本体を表示ONにする（詳細設定でOFFにできる）。撮影指示やスライド指示をCSPでは非表示にしたまま保存する用途に対応する。子の描画レイヤーの非表示は維持し、補正後の目玉をツリーに表示する。出力対象の工程・素材チェックは目玉を変更しない。

## CLIP単独の描画範囲

| 素材・効果 | 現在の処理 |
|---|---|
| ラスター、グレー／モノクロ、マスク | 256pxタイルと初期塗り色を復元。透明余白とマスクの既定色領域を切り詰め、座標を保持してメモリを節約 |
| テキスト | 保存済み画像を優先。一意なキャッシュと位置を照合し、同じ内容の重複キャッシュは統合。複数文字オブジェクトにも対応 |
| テキストの画像がない場合 | 文字列、フォント名、サイズ、色、配置、改行、横書きの行揃え、文字単位の書式から基本描画。未インストールのフォントは環境の代替フォントを使用 |
| 画像素材 | 保存画像がない場合、ResizableOriginalMipmapと四隅配置から復元。アフィン変形・遠近変形に対応 |
| レイヤーカラー | 描画用の主色・サブ色を読み取り、元画像の明度から色を置き換える。通常レイヤー・フォルダ・選択セル・工程に適用し、透明度とマスクを保持 |
| 境界線 | 保存された色・太さ、「描画の不透明度を反映」、アンチエイリアスから円形にフチを生成。選択セル・工程にだけ適用し、マスクも保持 |
| 水彩境界 | 「通常」の範囲・透明度影響・明度影響・ぼかし幅を読み取り近似描画。「ビビッド」など未対応の種類は元の描画を書き出す |
| トーン | 使用を検出して未対応と案内し、トーン化前の描画を書き出す。トーン生成は行わない |
| ベタ塗り・グラデーション | 保存画像を優先。画像がない場合は既知の塗り設定、線形・円・楕円と繰り返しから生成。曲線補間等は直線補間で近似 |
| 合成モード | Canvas対応分に加え、CLIPの減算、加算、発光、線形焼き込み、カラー比較、ビビッド／リニア／ピンライト、ハードミックス、除算を補完 |
| 色調補正 | 通常合成の階調反転・2値化を、現在の素材の重なりへマスク・不透明度付きで適用 |
| ベクター | 保存画像を優先。画像がない場合はストローク、筆圧・線幅・濃さの係数、埋め込みブラシ先端・紙質を使ってWorker内で近似描画。単一点も描画 |
| 3D | CLIP内のレイヤー単独の保存画像を使用。3Dモデル自体の再描画は行わない。画像がない場合は透明として扱い、保存状態に応じて案内 |

文字の縦書き、ルビ、厳密な禁則・字詰め・行間・装飾など、CSPの組版全体は再現しない。
3Dはレイヤー単独の画像を取得できなければ透明な画像として扱う。
質感、その他の色調補正・特殊素材には未対応の設定がある。
水彩境界は互換情報付きの保存画像にも適用されていなかったため、独自描画が必要。
レイヤーパレットのラベル色を描画用のレイヤーカラーとして誤用しない。

描画用レイヤーカラーは`DrawColorEnable`と`DrawColorMain/Sub`を使用する。
OFF時に保存色だけが残っていても適用せず、同じ色フィールドを使う用紙の塗りとは区別する。
各階層で「内容の合成 → レイヤーカラー → 境界線または水彩境界 → マスク」の順に処理する。
親フォルダの色はその内部の選択素材に適用し、外部の用紙や別トラックのセルを巻き込まない。
親子両方の色指定、主色・サブ色の変更、半透明画素、親子のマスクと無効化を純正保存結果で比較した。
検証した11状態では白背景で各チャンネル最大1階調差。すべての特殊効果との完全一致を保証するものではなく、
元画像自体が復元できない素材をレイヤーカラーだけで生成することはできない。

復元失敗や、保存画像のない文字・ベクター、水彩境界の近似、未対応のトーンは、該当レイヤーと影響する出力の警告に記録する。
読み込み時に判明した構造・タイムラインなどの診断は、ナビゲーター内の「再現状況」（狭い画面では中央のプレビュー上部）にも表示する。
レイヤーカラー・境界線の独自描画、成功した文字キャッシュ復元、意図的に適用しない撮影アニメーションでは警告しない。
PSD追加時は、実際にPSDの画像で置き換えた通常レイヤーの診断だけを除く。
フォルダ効果、画像を取得できなかった素材、タイムラインの診断は保持する。
同時読み込みでCLIPの画素展開を省略する場合も、フォルダを含む効果設定は解析する。
BINC 0110、重複区間、時間伸縮・未対応の補間などは引き続き制限がある。

出力一覧は現在の出力定義を順に確認し、問題がある場合だけ要確認の件数を表示する。
「確認中」「確認済み」「警告なし」のラベルは表示せず、確認処理中は一覧の`aria-busy`で通知する。
出力行とプレビュー名の三角から、その出力に参加する素材の復元失敗・近似描画・未反映の効果を確認できる。
一般のラスター復元失敗も追跡対象に含める。まだ読み込んでいない素材を成功と判定しない。
レイヤーツリーは診断の発生したレイヤー単体に三角を付け、子の警告を親フォルダへ集約しない。
フォルダ自身のマスク・効果などの失敗はそのフォルダに表示する。効果やマスクの使用自体では警告しない。
3Dは`Manager3D`または`Manager3DOd`の参照で判定し、保存画像を復元できる場合は警告しない。
画像を取得できず、互換情報の保存を確認できない場合には、CSPの［環境設定］→［ファイル］で
［バージョン互換情報の保存］を［保存する］に設定し、互換情報を含めてCLIPを保存し直して再読込する手順を表示する。
互換情報が保存済みの場合は、保存されていても画像を取得できなかったことを伝える。
PSDによる通常レイヤーの画像補完はヘルプに記載する。
CSP EX 5.1.5の標準3Dデッサン人形と立方体では、この設定で編集可能な3Dを保持したまま
原寸・透過のレイヤー画像が保存された。用紙の表示状態には依存せず、設定を［保存しない］に戻して
再保存すると画像がなくなった。キャンバス全体のプレビューや縮小サムネイルは代用しない。
この2素材の1920×1153pxのCLIPをアプリ画面から読み込み、3D単独を透過PNGへ書き出して、
CSPでラスタライズ後に書き出したPNGと比較した。完全透明画素のRGBを除くと、人形は差分なし、
立方体は2画素に最大1/255のRGB差分のみで、どちらも透明度は完全一致した。
全3D素材・描画設定での完全一致を保証するものではない。
通常の不明レイヤーを3Dだと推測しない。三角はクリック・キーボード・タップで詳細を開き、
素材の階層と原因を示す。「素材を確認」で単体プレビューを開ける。
Escape・外側の操作で閉じ、プレビューを押し下げない。
読み込み後の「確認しました」ダイアログは表示しない。警告は出力と素材のそばで繰り返し確認できる。
警告は合成に参加した素材を追跡し、選択外セル・非表示・不透明度0の素材は除外する。
上のレイヤーによる完全な遮蔽やマスク結果の画素単位の寄与判定までは行わない。

### 保存情報と案内の判定

`CanvasRenderMipmapForceSaved`から互換情報の保存設定を保存あり／保存なし／不明として取得する。
レイヤーごとの画像取得成否を優先し、保存ありだけで再現状況を消さない。
画像を取得できたベクター・3D・テキストには再保存を案内しない。
独自描画という実装上の理由だけでは案内せず、近似の差が大きい素材や未反映の効果を再現状況へ記録する。
水彩境界・トーンには互換情報による再保存を案内しない。未対応の効果だけではフォルダの隔離合成や画像座標を変更しない。
既に保存ありの場合は同じ設定を再度ONにする案内を繰り返さない。
判定は通常読込・PSD追加・タイムライン変更・クイック書き出しで共通にする。
クイック書き出しは全作品の処理後に案内を表示し、実際の合成に参加したレイヤーと出力ファイル名を記録する。
画像のない3D単独の出力も省略せず、キャンバス寸法の透明画像（白背景指定なら白画像）を生成する。

CSP EX 5.1.5で同じ非空の図形にレイヤーカラー・境界線・水彩境界を、通常レイヤーとフォルダの両方へ適用して比較した。
互換保存のON/OFFで効果なしの素材画像は変わらず、フォルダの原寸描画キャッシュは取得できなかった。
ネイティブPSDの再読込でもフォルダの3効果が欠けたため、PSD併用を全効果の解決策とは扱わない。
境界線は透明背景の孤立点・半透明面・円・斜線・αランプで太さとオプションを分離して検証した。
透明度ONは円形のα最大値、OFFは内外2つのα遷移と元の描画の合成を使う。一定値の内側を行単位の最大値で処理し、輪郭だけ距離による重みを評価する。
0.1〜6pxの検証画像ではアンチエイリアスONのα最大差は1/255。OFFでは高精度αの閾値付近に少数の二値差が残る。
完全透明な余白で平均差を薄めず、描画部分の透明度と黒・白背景の両方を検査する。全設定・全画像での一致を保証するものではない。
水彩境界は`EffectWaterEdge`を読み、同時に有効な`EffectEdge`を白い境界線として適用しない。
「通常」は非透明領域の内側に濃い縁を作り、乗算済みRGBAの縁をぼかして元画像へ加える経験的な近似。
範囲1・2・5・10、透明度影響1・5・50・94、明度影響0・20・50、ぼかし幅0.2・2・5・10の組み合わせをネイティブPNGで比較する。
細線・薄い輪郭には大きい局所差が残るため、再現状況の近似案内を継続する。作業バッファは周辺余白付きタイルで制限する。
境界線の透明度とアンチエイリアス設定は、`EffectLine`の後の別々の追加フィールドをネイティブON/OFF差分で確認した。

横書き・縦書きの文字は、互換保存なしでは文字オブジェクトのキャッシュ、ありではレイヤーの保存画像を取得できた。
検証文書では、クリスタでラスタライズしたPNGとの透明度差はなく、ブラウザ出力を黒・白背景へ合成した8bit値も一致した。
全フォント・装飾・組版を検証したものではなく、キャッシュを取得できない場合は基本描画へ戻して案内する。

### ベクターの近似と検証範囲

`VectorNormalStrokeIndex`と`VectorObjectList.LayerId`で識別する。`LayerType`のビットだけでは
マスク付き・マスクなしベクターを識別できない。既知の88/92バイトヘッダーと88/104/120バイト制御点を読み、
未知形式は診断へ記録する。単一点も描画し、ロック済み線幅・濃度係数は二重適用しない。
clip-tools由来の6点スプラインでは、制御点フラグのbit 0を角の境界として補間を区切る。
この処理は2文書の保存距離・乱数状態とPSD比較で検証したが、曲線補間全体は近似である。

CLIP STUDIO PAINT 5.1.5で新規の検証文書と複製サブツールを作り、同じ4ストロークに対して
UI設定を1項目ずつ変更した19状態のCLIP・PSDを採取した。座標・角・筆圧などの制御入力とシードの不変を
バイト差分で照合し、線幅など意図したヘッダー変更を別記した。前半は水平線だけ、後半は4本を編集した。
自動間隔への切替で連動して変わるBase・Effectorも記録し、無関係な独立変更として扱わない。
比較は透過PSDのアルファを使い、JPEGや座標の位置合わせは使わない。

追加試験では、作品と同じ画像先端・紙質を持つ229ストロークを新規文書へ複製し、11状態のCLIP・PSDを採取した。
用紙レイヤーの表示、先端の左右／上下反転、紙質倍率6.25%／100%／1000%、紙質の0／90度回転、
先端の乱数ON／OFFと0／90度、紙質濃度100%／1%を比較した。座標・制御入力・seedは不変だった。
紙質濃度はUIで1%が下限となったため、1%を紙質なしの対照とは扱わない。

| 対象 | CLIPに保存されるもの | 対照試験で確認し、反映した範囲 | 残る制限 |
|---|---|---|---|

押印は曲線に沿う距離で配置し、分割をまたぐ残距離を保持する。終点が間隔に一致しない場合に
余分な描点を足さない。単一点は1回描画し、重複制御点では押印を増やさない。
自動間隔はIntervalBaseに依存させず、有効な線径から計算する。
厚さ50%・径42px・狭い間隔では0.84pxになり、最小1pxより後に厚さが掛かることを確認した。

紙質は画像のアルファを双線形補間する。濃度1で乗算は`coverage×grain`、通常は
`clamp(coverage×(0.5+grain))`に一致する。濃度0では中立、中間の濃度は中立値との線形補間で近似する。
通常の係数は1を超えるため、係数ではなく描点の濃度に掛けた後にクランプする。
未知の紙質設定・画像の欠落・不正な値は診断する。描点ごとの適用自体は未対応警告の対象から除いた。

250×250pxの紙質を6.25%にした対照では、出力画素の紙質が31pxごとに繰り返された。
連続的な15.625px周期のまま読む旧方式ではこの位相を保てなかったため、
`max(1, floor(元寸法×倍率×2))/2`の周期と、縮小時の周期的なボックス平均で近似する。
この式からCSP内部の処理解像度やカーネルが一意に判明したとは扱わない。
今回のCLIPにあるMipmapの縮小段には寸法情報があっても再利用できる画素がなく、元画像からフィルターを生成した。
先端の2倍格子も対照に基づく近似であり、保存座標や比較画像を平行移動する補正ではない。

用紙レイヤーの表示ON／OFFで、PSD内の対象ベクターレイヤーのRGBAは完全一致した。
この条件では用紙色の背景合成と、ブラシ設定の紙質は独立している。用紙を先端画像へ焼き込む処理は加えない。

乱数は`state = (state * 0x41C64E6D + 0x12D687) mod 2^32`で更新し、
`((state >>> 16) & 32767) / 32768`を使う。ストローク単位でseedへ戻す。
濃度だけをランダムにした点、向きも有効にした点、最小濃度50%の点で、濃淡と消費順を照合した。
`RotationEffector=3`の「なし」は基本角度を固定し、曲線接線へ追従させない。
他の角度方式、散布、複数先端、混色などは完全再現せず、ベクター全体の「近似描画」表示を継続する。

細い硬質ペン（先端・紙質画像なし、AA=1、Hardness=1、ThicknessBase=1、CompositeMode=31、径4px以下）の
線幅0.65倍・不透明度0.9倍補正は以前の経験式を保持する。今回確認した通常合成の丸ペンとは適用範囲が異なる。
この補正をCSPの仕様として扱わない。先端画像欠落時は丸ペンに代替し、診断する。

#### PSD比較の結果

指標はアルファのsoft Dice = `2Σmin(a,b)/Σ(a+b)`。白い余白の一致で水増しせず、
描かれた線の濃淡と重なりを測る。画素が完全一致した割合ではない。

- 新規の対照19状態は、各画像全体で99.1〜99.99%。円形の単独点は画素一致。
  速度で線幅が変わる部分、扁平な点の縁には差が残る。全ブラシへ一般化できる結果ではない。
- 画像先端の追加対照11状態は、変更前84.16〜88.25%→93.23〜95.69%。
  作品と同じ6.25%・乱数角度の対照は85.62%→94.93%、アルファ総量はPSD比1.037倍→1.001倍。
- 非公開の23ベクターレイヤー・4,633ストロークは、追加試験前85.16%→94.79%。
  アルファ総量はPSD比1.035倍→1.000倍。紙質を扱う前の最初の実装は71.07%だった。
- 別作品の27レイヤー・1,276ストロークは91.38%→92.96%。
  画像ブラシ7層は75.83%→80.67%、丸ペン20層は97.12%のまま画素も不変。
  2px未満の極細線で補正による後退があったため、この指定径は従来の形状・AA・角度を保持する。
  両作品ともベクターレイヤー全体の画素完全一致には達していない。

公開リポジトリには作品のCLIP・PSDや紙質素材を含めない。
新規に作った単純な水平線のPSDから、アルファ領域だけを圧縮した小さいゴールデンデータをテストに保持する。
固定／自動間隔、乱数、丸い点の濃淡、速度カーブの格納順、紙質の適用順を回帰検証する。
画像先端の反転・回転・縦横比、画像を共有するスタイルの独立性、紙質の縮小周期と継ぎ目は合成データで検証する。
描画は16 Mpxキャンバス・1ストローク16 Mサンプルを上限とし、ストローク境界内だけを高解像度化する。
制御点数・累積サンプル数・描画演算量にも上限を設ける。

### 保存データの読み取りと、描画仕様の解読は別

今回の不足の多くは「CLIPに情報がない」ことではなく、保存値の意味・単位・適用順が未反映だったことにある。
SQLite列と画像を読み取れることだけで、ベクター再現情報を解読しきったとはいえない。
一方、確認した保存構造にはCSPの実行可能な描画アルゴリズムはなく、押印・濃度合成・AA・フィルターの
計算手順は、保存入力と対照PSDに合うようエンジン側で再現する必要がある。

制御点末尾の+76（f32）は次の描点までの残距離、+80（u32）は乱数状態として、
新規の固定／自動間隔・乱数変更と整合した。画像ブラシの+84（u32）は進行カウンターに対応するが、
今回の丸ペンでは乱数有効時も0のままだった。すべてのブラシに共通する押印数とは扱わない。
既存23層の33,582区間で乱数がカウンター増分の2倍進み、別作品の画像ブラシ4,779区間では1倍進む。
新規対照の向き→濃度という消費順はこの違いと整合する。
保存キャッシュを直接描画の根拠にはせず、設定の意味と生成した押印列を検査する証拠として使用する。
編集後の有効性・更新条件、曲線長の残差は引き続き未確定である。

`StyleFlag & 4`はUIの「間隔によるブラシ濃度調整」に対応したが、固定間隔50%の対照ではPSDに差が出なかった。
この条件だけで一般式を決めず、未反映の仕様として残す。
画像先端のかすれ・再サンプリング、全AA・極細線、非線形グラフ、その他のフラグにも未解読部分がある。
これらは「必要情報がCLIPに保存されない」と断定できない。

CSP画面上の項目は[ストローク設定](https://help.clip-studio.com/en-us/manual_en/810_subtools/S.htm)、
[ブラシ設定](https://help.clip-studio.com/en-us/manual_en/810_subtools/B.htm)、
[紙質設定](https://help.clip-studio.com/en-us/manual_en/810_subtools/T.htm)を参照できる。
これらの説明はCLIPの数値列挙値や描画アルゴリズムの定義ではなく、上記の対応は対照試験から得たものである。

入力1 GiB、SQLite 256 MiB、画像1枚64メガピクセルの検査は維持する。
CLIPはWorkerに圧縮データと解析済みメタデータを保持し、素材単位の要求で画素を転送する。
SQLiteはメタデータ取得後に閉じる。Workerの作業画像・ブラシ画像は要求間で保持しない。
PSDは圧縮チャンネルを保持し、元データを破壊しないアダプターで必要なレイヤーだけ復元する。
ZIPチャンネルの展開長は引き続き小さいチャンク単位で検査する。

描画前に通常の選択・工程・コンテキスト・仮想セルの走査を画素生成なしで実行し、必要な素材を準備する。
合成中に使う素材は固定し、同時に複数の準備処理を走らせない。素材キャッシュの通常予算は192 MiB。
一画像の処理中はこれを超えて必要な素材を保持できるが、素材の同時保持は768 MiB、
同期合成中の一時canvasは512 MiBまでとし、終了時に通常予算まで解放する。
これらはアプリが管理する画像領域の値であり、ブラウザ全体のメモリ使用量ではない。
キャッシュ解放では診断結果を保持し、次回は圧縮素材から再生成する。
素材を借用するコンテキストキャッシュも解放世代を検査し、解放済みcanvasを再利用しない。

チャンク、CRC、配列長、再帰深度、リンク循環、展開長を検査し、Worker要求は各2分でタイムアウトする。
ベクターは実際に確保したFloat32タイルに256 MiBの作業上限を設ける。
単一素材の展開・合成用メモリ・Workerの失敗は再試行可能なエラーとして出力を中止し、
恒久的に欠けた素材や透明画像の成功として扱わない。
文書切替・PSD差替えで古いWorkerと素材キャッシュを破棄する。作品データの外部送信や元ファイルの変更は行わない。

## 検証

- `public/sample/c001.clip`はアプリとテスト共通の公開サンプル。
  純正PSDの全36レイヤー・3つのセルフォルダと照合し、演出Aと作画Aを区別する。
- CLIP＋PSDとPSD＋XDTSを、セル名・連番・連番（シート合わせ）の3方式で比較。
  出力パス・名前・RGBAのSHA-256が一致する。
- c001の9枚のゴールデンPNGに対し、PSD＋XDTS、CLIP＋PSD、CLIP単独の全方式で
  既存の1階調許容差を満たす。
- 同梱テンプレートの9つの同名Aフォルダ、負のキー、時間移動を検証。
- セル内部の同名フォルダ、非表示工程の採番、複数タイムラインと手動の目の保持、
  文字画像なしの描画、静的配置、境界線とマスク、発光、補正、グラデーションを検証。
- 人工のライトテーブル参照を含むCLIP構造で、参照画像の除外・参照元セルの保持・PSD照合を検証。
- `testdata/layer-color`の人工素材とCSP保存プレビュー11状態で、レイヤーカラーの色・適用順を比較。
  個別出力、親階層、マーク、仮想セル、出力プレビュー、PSD併用時の二重適用防止も検証。
- Web版でCLIP単独、PSD追加、従来形式への切り替え、サンプルボタン、実ZIP保存を検証。
  デスクトップ用CSPを適用したブラウザでもWorker/WASMの実行を検証する。

EXEへ複数のCLIP単独／CLIP＋PSDを混在してドロップするクイック書き出しに対応する。
複数作品は同じフォルダ・同名（拡張子を除く）で対応付ける。Windowsパスは大文字・小文字を区別しない。
指定したファイルだけを処理し、周囲のPSDは自動検索しない。対応先がないPSD/XDTSや曖昧な重複入力は失敗として表示する。
1作品だけを明示指定する従来のCLIP＋PSD、PSD＋XDTSは、ファイル名が異なる組も引き続き受け付ける。
複数のPSD＋XDTSだけのバッチ処理は対象外。CLIPと併用された同名XDTSは従来どおりCLIPを優先する。
読み込み・構造照合・合成・保存を1作品ずつ行い、作品ごとに画像と状態を解放する。
保存済み設定を各作品の開始時に復元し、複数タイムラインの兼用カット自動ONなどを次の作品へ持ち越さない。
CLIPと同じ場所へCLIP名で出力し、既存フォルダは連番で回避する。従来のPSD＋XDTSではXDTSの場所へ出力する。
作品単位の失敗は残りの処理を中断せず、結果一覧に入力・出力先・枚数・エラー・CLIP解析の診断を表示する。
保存途中の失敗では途中まで作成した出力フォルダが残る場合がある。再実行では新しい出力フォルダを作る。
EXEのビルドと起動引数の処理テストは、EXE自体の画面操作による確認とは区別する。
