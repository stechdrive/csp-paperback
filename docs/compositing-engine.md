# CSP Paperback 合成エンジン設計ドキュメント

このドキュメントは CSP Paperback の合成エンジン（`src/engine/`）の設計思想・処理フロー・ルールを記述する。
コードの「なぜ」を保存することが目的であり、コードのリファレンスではない。

---

## なぜこのツールが必要か

クリスタはアニメーション制作ツールだが、制作フローの多くの工程で静止画が必要になる。

- 仕上げ工程はクリスタ以外のツールを使うことが多い
- 撮影工程は静止画の合成
- 次工程が紙（印刷）の場合もある
- 外部スタッフがクリスタを持っていない場合もある

つまり **「クリスタで作ったアニメーション素材を、静止画として正しく取り出す」** というニーズは制作フローの構造的な問題として存在する。

---

## 現場のワークフローと課題

### 別トラック方式（従来）

クリスタのアニメーション書き出しはタイムシートに打たれた「セル単体」を出力する設計になっている。
そのため、原画・演出修正・作監修正など複数の工程が絡む場合、現場では以下のような構造をとる。

```
レイアウト/
  LO/
    A/
      1番  2番  3番  ...

  演出修正/
    A/
      1番（修正あり）  3番（修正あり）  ...

  作監修正/
    A/
      2番（修正あり）  ...
```

修正が発生したセルに、修正工程のタイムライン上の同じコマに別トラックでセルを置く。
クリスタの書き出しで自動化でき、静止画として次工程に渡せる。

これは出力の自動化を見据えると効率的だが、紙の作業工程の再現という観点では直感的ではない。タイムシートの複製が煩雑であり、修正指示が同一のレイヤーフォルダで管理できなくなってしまう。

### セル内包型（理想構造）

各工程をセルの中に従属させる構造。

```
A/                         ← アニメーションフォルダ
  1/                       ← セルフォルダ
    _作監修正/
      修正線画
    _演出修正/
      修正線画
    原画本体レイヤー
```

構造として直感的だが、クリスタのアニメーションセル書き出しでは工程ごとの独立した出力が自動化できない。全工程を合成した画像が1枚出るだけで、修正指示を単独で確認することができない。また、作業途中に視認性のため別工程の素材の不透明度を下げた状態で保存していると、その影響が出力に混入する。

### このツールが解決すること

両方のワークフローに対応し、どちらで作られたデータからも工程ごとの完成画像を正しく取り出す。

- **別トラック方式**: CLIPからアニメーションフォルダとタイムラインの対応を読み込み、修正工程のフォルダ名をprocessTableに登録することで出力ファイル名に自動サフィックス付加
- **セル内包型**: セル内の工程フォルダ名をprocessTableに登録することで検出・独立出力。構造コンテナの不透明度は100%固定、アートワークの不透明度は尊重

工程フォルダ名は、素材側・辞書側ともに前後の空白（半角・全角スペース、タブ等）と大文字小文字を無視して照合する。たとえば末尾に空白が付いた「作監 」も登録名「作監」に一致する。別トラックの親工程、セル内工程、自動検出、辞書の重複チェックで同じ照合キーを使い、空白だけの辞書名は無視する。元のフォルダ名、名前の途中の空白、出力サフィックスは変更しない。

## メンタルモデル：「紙に戻す」

CSP Paperback の出力は **「作画用紙に描いた1枚の状態」** を再現することが目標である。

CSPの作業ファイルには「作業用の透かし」「参考素材の半透明表示」「工程フォルダのネスト構造」など、出力とは関係ない情報が含まれている。これらを取り除いてタイムシートどおりの、作画、演出、作監といった修正工程ごとの画像を得るのがこのツールの役割。

この目標から以下の方針が決まる：

- **合成モードはすべて尊重する** — 作業者が意図して設定した合成関係は出力にも反映する
- **不透明度はレイヤーの役割によって扱いが異なる**（後述）
- **非表示レイヤーは合成不参加** — UIで隠したものは出力にも出ない（作業者の自己責任）

### 表示と出力対象

読み込み時は `showIndividualFoldersOnLoad`（未設定はON）に従い、個別書き出し対象の非表示フォルダ本体を表示ONへ補正する。ツリーの目玉にも補正後の状態を反映する。描画レイヤーの非表示は保持する。`archivePatterns` に前方一致するフォルダは子孫にも除外理由を引き継ぎ、自動の工程・個別書き出し・アニメーション出力の検出と自動表示の対象外にする。設定変更は素材の再読み込みで反映する。

保管用フォルダ内の `_k` や `_ss` だけでは工程チェックを作らない。除外配下にCLIP／XDTSのアニメーションフォルダがあっても、出力候補・巡回・実書き出しへ自動追加しない。素材の表示や合成そのものを禁止する設定ではなく、手動で個別出力・アニメーション出力を指定したものや、仮想セルで参照した素材は引き続き使用できる。

出力対象は `output-target.ts` の共通分類・判定を、ファイル一覧、プレビュー、巡回、実書き出し、ツリーの状態表示で共有する。

- `excludeBody`: 修正工程に属さない通常アニメセルの本体だけを除外する。同じセル内の修正出力を落とさない。
- `excludedProcessSuffixes`: 親工程・セル内工程・自動アニメ化した素材の直下工程に対して適用する。空文字の工程も本体とは区別する。
- `individualOutputOverrides`: 先頭の `_` を外し、前後空白と大小文字を正規化した素材名ごとの出力ON／OFF。整理専用親は項目に含めない。自動アニメ化したBGなども個別素材として扱い、工程チェックと組み合わせる。
- 旧 `excludeAutoMarked` は、個別素材名の指定がない場合の既定値として読む。工程名にも一致する個別素材の旧除外を保持し、同じ工程内でON／OFFが混在する場合は中間状態を示す。工程チェックをONにすると該当素材もまとめてONにする。手動指定の旧例外を維持し、素材名の明示指定を優先する。

チェックは表示状態を変更せず、合成用素材の取り扱いも変更しない。ツリーは「出力OFF」「一部OFF」を目玉とは別表示する。検出候補は出力フィルター適用前・非表示込みで収集し、OFFにした項目を一覧から消さない。仮想セルはこれらの分類外で従来どおり独立して出力する。

工程の `displayName` はUI専用。省略された旧JSONは、`_`で始まらない登録名、次にサフィックスから表示名を解決し、照合・出力名は変更しない。

### 素材の準備と解放

CLIP／PSDの通常読み込みは圧縮素材を保持し、描画に必要なレイヤーを後から展開する。
`material-dependencies.ts` の収集モードで通常の描画関数を走査し、画素を生成せずに必要素材を確定する。
`flattenTree`、仮想セルの上書き走査、セル／アニメフォルダのマスク、祖先の素材効果を同じ経路で扱う。
収集には新しいコンテキストMapを使い、描画キャッシュを参照して依存元を取り落とさない。

素材準備と同期合成は直列化する。準備中の素材はその画像の合成が終わるまで解放しない。
素材の座標・復元結果は元のLayer参照で管理し、表示変更やUndoで複製されたツリーへも適用する。
素材キャッシュが画像を解放したら、借用画像を持つコンテキストは次回描画前に破棄する。
完成済みの出力画像は独立したcanvasなので、素材の解放や再読込で変更されない。
未読込・読込中・解放済み・読込失敗を区別し、メモリ不足の素材を透明画像として成功させない。
通常の一般ラスター復元失敗にも合成元IDを残し、出力に欠けた素材の診断を表示する。

### 出力一覧・プレビュー・合成元の対応

`output-plan.ts` の同じ出力定義から、出力一覧、中央プレビュー、サムネイル、実書き出しを作る。出力IDはファイル名や行番号から独立し、セル内工程ではアニメフォルダID・セルID・工程サフィックスで識別する。同じ工程に複数の別名フォルダが一致していても、先頭のフォルダを非表示にしただけでは選択IDが変わらない。

出力一覧のDOMは表示範囲と前後240pxを仮想化する。選択中の行は画面外でも1行だけ保持し、`aria-activedescendant` と接続線の「選択中の出力へ戻る」を維持する。検索・範囲選択・全選択・キー移動・書き出しはDOMではなく全件の出力定義を対象にする。行の折り返しと未配置セルの見出しは実寸を測り、幅・フォント・一覧の変更で高さを再計算する。位置の補正後は接続線にも通知する。アンマウント時にはサムネイル用canvasと購読を解放し、再表示時には既存の画像キャッシュを使用する。

ファイル名の衝突解決は全件の出力定義に対して行い、選択書き出しではその後に対象を絞る。ZIP／フォルダ保存には確定済みの名前を渡す。書き出し用canvasは毎回独立して生成し、保存処理による参照解放をプレビューのキャッシュと共有しない。

画像キャッシュの `renderKey` は出力定義オブジェクトやファイル名から独立する。JPG品質、同じ背景のままの形式変更、命名、フォルダ分け、出力対象の除外・復帰、仮想セル名の変更では画像を再利用し、一覧の名前と保存設定は最新の定義を使う。キーには表示・外観・マークを反映したツリーの識別子、文書寸法、背景、工程の分割規則、仮想セルの描画設定、実際に適用する確認フチ色を含める。工程のUI表示名やフチ色だけでは自動アニメ化のツリーを作り直さない。キーはピクセルを含まず、ツリー識別用WeakMapも古い文書を保持しない。将来、描画に影響する設定を追加する場合はキーの依存条件にも追加する。

接続線の根拠は `render-sources.ts` が実際のflatten・合成処理から収集する。非表示や別出力として除外された枝をUIの階層探索だけで復元しない。Pass Throughの構造、隔離合成、マスク・描画効果の中間canvasにも素材IDを引き継ぎ、セル素材と共通コンテキストを区別する。透明度やクリッピングによる最終的な画素寄与率の解析ではなく、合成処理に参加した素材の記録である。

中央の出力ID、複数選択、素材の編集対象、仮想セル・メンバーの編集対象、Quick Lookは別の状態として保持する。素材の選択ではタイムラインを移動せず、出力一覧・タイムライン・Shift巡回からの操作だけで出力選択を更新する。無効になった出力は別画像に置き換えず、表示や工程設定を戻すと同じIDで復帰する。

描画キューは中央画像を優先し、表示範囲のサムネイルを画像単位で順次処理する。同じ出力に対する同時予約は一度の合成から各解像度へ縮小し、完了通知はその画像・解像度を表示する購読者に限定する。サムネイルの可視判定は一つのIntersectionObserverを共有する。キャッシュ予算は48MiB・256項目で、表示中の画像は保持する（原寸画像や表示中の合計が予算を超える場合もある）。並べて表示は8件まで・長辺1024px、サムネイルは長辺160px。縮小用の一時原寸画像、非表示ペインの描画先はすぐに縮小してメモリを解放する。画面外へ移った描画予約を取り消し、文書の読み直しでキャッシュを破棄する。入力素材や共有中の画像は解放対象にしない。Canvasによる1画像の同期合成自体は途中で中断しない。

完成画像とは別に、共通コンテキストのマスク・描画効果を適用済みの素材をプレビュー間で再利用する。上下のレイヤー配列と祖先フォルダの境界を保ち、背景全体を1枚に潰して合成順やPass Throughを変更しない。描画済みの中間画像は、有効領域と整数座標の配置が分かる場合に透明余白を切り詰める。元画像と端数座標で配置する画像は切り詰めない。

元画像が不変の通常素材は、水彩境界・境界線・レイヤーカラーの処理結果も再利用する。キーには画像の識別子・寸法・位置・文書寸法・効果設定を含め、選択セルを含む一時的なフォルダ合成には使わない。共通コンテキストと素材効果を合わせた中間画像の通常予算は24MiB、コンテキストは最大8件、素材効果は最大64件とする。4K画像の反復処理を避けるため、所有する画像が1枚だけの場合は64MiBまで保持する。同じcanvasへの複数参照は容量を重複計上しない。読み込み済みの素材は借用し、キャッシュが生成した画像だけを所有・解放する。解放は同期合成の完了後に行う。文書切替では画像キャッシュとセレクターの元ツリー参照を全破棄する。描画キューの統計は完成画像と中間画像の保持量、素材効果の再利用回数を返す。

同期合成中に生成したcanvasを追跡し、最終画像と保持するコンテキスト以外は処理の終了時（例外時も含む）に縮小する。フォルダ内の一時合成も同様に解放し、クリッピング・補正・独自合成の作業canvasは使用直後に解放する。マスクとレイヤーカラー・境界線の画素読み戻しは、描画内容の保守的な矩形とフチ幅に絞る。出力canvasの寸法・座標は変えない。端数座標のマスクはCanvasの補間結果を保つため、マスクの作業面を文書寸法のまま維持する。入力画像・表示中の画像は、この一時解放の対象にしない。

中央の全体プレビューを新規文書の初期表示とし、出力一覧の選択で出力表示へ切り替える。並べて表示は出力一覧の順を保ち、ペインの幅・高さとズームから列数を再計算する。右ペインの接続表示は縮小画像に付随する合成元情報を使い、接続線だけのために原寸画像を保持しない。

通常ウィンドウの書き出しでは `planExportEntriesFromState` で名前と対象を確定し、保存先の選択後に1枚ずつ合成・画像変換・保存する。工程フチ適用後の書き出し専用canvasは変換後に解放し、隣接セルで使う背景コンテキストは最大2項目を再利用する。各画像の処理前にイベントループへ制御を返して進捗を描画する。プレビューの待機ジョブは書き出し中だけ停止する。通常UIはinertとグローバル入力ガードで保護し、ファイル再投入とUndoも停止する。成功・失敗・保存先キャンセルのいずれでもfinallyでロックを解除する。ZIPのダウンロード方式によっては圧縮済みアーカイブ全体のBlobが必要であり、入力データや背景コンテキストを含めたアプリ全体のメモリが画像1枚分になるわけではない。

書き出し用の共通コンテキストと素材効果にも同じ24MiBの通常予算・単一画像64MiBの上限を設け、保存ストリームの完了・中断・失敗で解放する。JPGのJFIF密度とPNGのpHYsは必要なヘッダーだけを読み、圧縮済み画素をBlobの部分参照として組み直す。画素データ全体の配列コピーを作らず、DPI値・PNGのCRC・既存のチャンク順序を維持する。

デスクトップのZIP保存は、選択した保存先を切り詰めてからストリームを書き込み、成功・失敗のどちらでもファイルを閉じる。大きなZIPから小さなZIPへ上書きした場合も、以前の末尾やファイル一覧を残さない。

未配置の仮想セルは従来のグローバルコンテキストで確認できるが、実書き出しの定義には含めない。Quick Lookは選択した素材のルートだけ一時的に表示し、子の目玉・合成モード・不透明度・効果を保った素材単体の確認とする。仮想セルのメンバー確認にはそのセル独自の設定を使い、文書・Undo履歴・中央の出力選択には書き戻さない。

デスクトップのクイック書き出しも同じ `planExportEntriesFromState` と逐次保存処理を使う。全画像を先に合成せず、保存済み設定と全件で確定した名前で1枚ずつ出力し、画像変換の終了時に専用canvasを縮小して解放する。保存先への書き込み完了後に次の画像へ進み、作品単位の失敗記録・次作品の続行・作品間の状態解放を維持する。

## レイヤーの役割分類と不透明度ポリシー

アニメーションセルの構造には「構造的コンテナ」と「アートワークコンテンツ」の2種類がある。

```
A/           ← アニメーションフォルダ（構造的コンテナ）
  1/         ← セルフォルダ（構造的コンテナ）
    _en/      ← 演出修正工程フォルダ（構造的コンテナ）
      レイヤー3       ← アートワーク
    レイヤー2         ← bodyLayer（アートワーク）
    ベタ塗り/         ← 非工程フォルダ（アートワーク）
      ...
```

| レイヤー種別 | 不透明度 | 根拠 |
|------------|---------|------|
| アニメーションフォルダ本体 | **100%固定** | 構造的コンテナ。紙に戻すという前提で考えると100%以下にする理由がない |
| セルフォルダ（直接の子） | **100%固定** | 同上。extractCellsでは子のみを処理対象とし、フォルダ自体は合成対象にならない |
| アニメフォルダ直下の単体セルレイヤー | **100%固定** | セル画像として構造的扱い（レイヤーフォルダをつくらず一枚のレイヤーのみで作画したセル番号の素材） |
| 工程フォルダ本体（`_en/` 等） | **100%固定** | 構造的コンテナ。工程を束ねる入れ物 |
| セルフォルダ内のbodyLayer | **尊重** | 作業者の意図（影付素材を半透明にして作業する等）を反映 |
| 工程フォルダの中身 | **尊重** | 同上 |

### なぜ構造的コンテナを100%固定にするのか

作監修正時に「その他工程の素材を視認性のために不透明度50%にして作業中に保存した」場合、
そのセルフォルダや工程フォルダが50%になっていても出力は100%として扱うべき。
ユーザーが意図的に下げたのではなく、作業上の都合で設定された値だから。演出修正やもとのレイアウト素材を「紙」に戻すなら、それが薄くなっているなんてありえない、という理由。

bodyLayerは逆に、作業者が意図的に不透明度を設定した結果を尊重する必要がある
（例：影レイヤーを半透明にして色の調整をしている等）。

### 実装上の不透明度制御

`flattenTree` は `extraIgnoreOpacityIds` パラメータで制御する。

- **グローバルプレビュー（ナビゲーター）**: `extraIgnoreOpacityIds` なし → 全レイヤーの `layer.opacity` をそのまま使用。PSDの生の状態を表示する
- **出力プレビュー・実出力**: `extractCells` 経由 → 構造コンテナのIDを `extraIgnoreOpacityIds` に渡して100%強制

```
effectiveOpacity = extraIgnoreOpacityIds?.has(layer.id) ? 100 : layer.opacity
```

## flattenTree の動作ルール

`flattenTree`（`src/engine/flatten.ts`）はレイヤーツリーを `FlatLayer[]` に変換する。
プレビュー用（1フレームを1枚に）の関数であり、出力用の `extractCells` も内部で利用する。

各レイヤーは以下の優先順で処理される：

```
1. hidden || uiHidden → [] （合成不参加）

2. isAnimationFolder
   → 選択セルを flattenLayer で再帰処理
   → compositeGroup で1枚に合成
   → アニメフォルダ自身のマスクを適用
   → FlatLayer 1枚で返す（プレビュー専用。出力は extractCells が担当）

3. isFolder && animAncestorIds.has(id)  ← アニメ包含フォルダ（例外ルール）
   → 子を個別に flattenLayer して結果をそのまま返す（中間合成しない）
   → このフォルダ自身の合成モード・マスクは無視
   理由: このフォルダを1枚に合成してしまうとアニメフォルダの独立した合成ができなくなる

4. isFolder（通常フォルダ）
   → pass through: 子を展開してそのまま返す（中間キャンバスなし）
   → 非 pass through: 子を compositeGroup で1枚に合成 → フォルダのマスクを適用 → FlatLayer で返す

5. 通常レイヤー
   → canvas, blendMode, opacity（ポリシー適用後）, mask を FlatLayer に変換
```

### 処理順序

ツリーはトップファースト順（PSDのレイヤーパネルの表示順）で格納されている。
合成はボトムファースト（下のレイヤーから先に描画）で行う必要があるため、
`flattenTree` は `rootChildren` を逆順にイテレートする。

### Pass Through フォルダのマスク制限（v1）

Pass Through フォルダにマスクをかけると、本来は「フォルダ内の全レイヤーを
背景込みで合成した結果にマスクを適用する」挙動になる。
これには中間キャンバスと背景の状態への依存が必要で実装コストが高い。
実際の作業ファイルでこの設定が使われることはほぼないため v1 ではスキップしている。

## 出力パイプライン

### extractCells — アニメーションフォルダからセルを抽出

`extractCells`（`src/engine/cell-extractor.ts`）はアニメーションフォルダの各可視セルを独立した `OutputEntry` に変換する。

セルの種別はPSD構造から自動判定する（明示的なモード選択はない）。

```
extractCells(animFolder, projectSettings, ...)

for each visibleCell in animFolder.children:

  [A] 単体レイヤーセル（cell.isFolder === false）
      flattenCellContent([cell], ignoreOpacity={cell.id})
      → applyContainerEffects（セルフォルダ・アニメフォルダの効果とマスク）
      → compositeWithContext(lowerContext, upperContext)
      → OutputEntry 1件

  [B] フォルダセル（cell.isFolder === true）
      子をprocessTable照合で分類:
        processGroups: フォルダ名がprocessTableにマッチ → 工程別出力
        bodyLayers: それ以外 → 本体出力

      本体出力（bodyLayersがある or processGroupsが空）:
        flattenCellContent(bodyLayers)  ← opacityをそのまま尊重
        → applyContainerEffects
        → compositeWithContext
        → OutputEntry 1件

      工程別出力（processGroupsの各suffix）:
        flattenCellContent(processLayers, ignoreOpacity={processFolder.id})
        → applyContainerEffects
        → compositeWithContext
        → OutputEntry 1件（suffix付きファイル名）
```

### applyContainerEffects の役割

`extractCells` はアニメフォルダをレイヤーとして `flattenLayer` に通さないため、
アニメフォルダ本体のマスクとセルフォルダ（非 pass through）のマスクが
自動的に適用されない。`applyContainerEffects` がこれを補う。

適用順序（グローバルプレビューの flattenLayer 処理順に一致させる）：
1. セルフォルダの内容を合成し、CLIPのレイヤーカラー・境界線を適用
2. セルフォルダのマスク（非 pass through、または描画効果のあるフォルダ）
3. アニメフォルダのレイヤーカラー・境界線とマスク

CLIPの効果がある場合は選択素材だけを隔離合成し、コンテナの合成モードを保持する。
構造コンテナの不透明度は引き続き100%。単体セルの効果は`flattenTree`で一度だけ適用する。
描画用レイヤーカラーを持つ祖先がある場合、`collectMaterialOutputContext`で内側から外側へ
兄弟コンテキストを収集し、各フォルダの範囲で色とマスクを適用する。
その外部にある用紙やコンテキストは親フォルダの色変換に含めない。
PSD入力・CLIP＋PSDではネイティブ効果を持たないため、従来の合成経路を使う。

### extractAllEntries — 全出力エントリの生成

`extractAllEntries` はツリー全体を走査して全出力エントリを生成する。実出力のメインエントリポイント。

```
走査ルール:
  - isAnimationFolder → extractCells で処理
  - autoMarked || singleMark → collectMarkedLayerContext で合成コンテキストを取得し出力
    （読み込み時に特定したアニメフォルダは `_` プレフィックスより優先してセル出力）
  - isFolder && hasAnimFolderDescendant → 子を再帰走査（兄弟コンテキストを継承）
  - isFolder（アニメ子孫なし） → 子を再帰走査
```

### CLIPのフォルダ識別と手動指定アニメーションフォルダ

CLIP入力では、ネイティブのフォルダ種別とIDからアニメーションフォルダを識別し、選択したタイムラインのトラックを対応付ける。純正PSDを追加しても、この対応はCLIPから取得する。アニメーションフォルダの直接の子がセルであり、セル内部の整理用フォルダを別セルとして扱わない。

出力・プレビューでは名前から再マッチングせず、ツリー上の `animationFolder.trackNo` を参照する。CLIP内のタイムラインを切り替えると、対応と初期表示を再計算する。「兼用カット」では未使用セルを初期OFFにせず、保存時に表示されているセルも出力できる。詳細は[CLIP読み込みの実装仕様](clip-import.md)を参照。

手動指定アニメーションフォルダは、読み込み時の識別結果の後段に重ねるアプリ独自のオーバーレイである。既存のアニメーションフォルダ、その祖先・子孫には重ねない。自動単体マークがあるフォルダでも、手動アニメーションフォルダとして指定された場合はセル出力を優先する。

内部互換用のPSD＋XDTS入力では、従来どおり読み込み時にトラックとPSDフォルダを照合して `trackNo` を確定する。この経路の兼用カットでは、対応したフォルダ本体が非表示でも初期表示ONとし、配下セルはPSDの表示状態を尊重する。

### 自動マークフォルダの工程フォルダ自動判定

`_` で始まるフォルダ、またはプロジェクト設定の自動マークフォルダ名に完全一致するフォルダ（単体出力の対象）のうち、**直接の子にプロジェクト設定テーブル（工程テーブル）登録名のフォルダを持つもの** は、アニメーションフォルダとして自動的に扱う（実装は `promoteAutoMarkedByProcessMatch`）。自動マークフォルダ名は trim + lowercase で完全一致し、初期設定は `撮影指示` と `原図`。除外リストは `_` と登録名のどちらよりも優先される。これは「作画マンの背景原図と、それに対する演出修正（`_e/` 等）を別々の紙として出力したい」というユースケースを、明示的な手動指定なしで満たすための機構である。

判定ルール：

1. **既にアニメーションフォルダに確定済み** なら対象外（読み込み時の識別・手動指定を優先）
2. **祖先のいずれかがアニメーションフォルダ** なら対象外（CSP仕様「アニメーションフォルダ内にアニメーションフォルダは含まれない」に準拠）
3. **子孫に既にアニメーションフォルダを含む** なら対象外（読み込み時の識別・手動指定・内側の自動アニメ化を優先）
4. **直接の子のみ**を工程テーブルと照合（孫は見ない。trim + lowercase で照合）
5. 工程テーブルが空なら一切発動しない

判定成立時：

- `layer.isAnimationFolder = true`
- `layer.autoMarked = false`（単体出力マークは解除され、アニメセル出力パイプラインに乗る）
- `layer.animationFolder = { detectedBy: 'autoProcess', trackName: layer.originalName }`

アニメーションフォルダ特定と自動出力の優先順位：

```
CLIP識別（互換入力ではXDTS検出）> 手動指定 > 工程フォルダ自動判定（子孫アニメフォルダ優先）> 整理用自動マーク親フォルダ抑制 > 単体出力の自動マーク
```

自動判定は `selectLayerTreeWithVisibility` 内で読み込み時の識別・手動指定の反映後に適用される。既に確定済みのフォルダはスキップされるため、優先順位が保たれる。

### 整理用自動マーク親フォルダの抑制

自動マークされたフォルダのうち、直下の表示中要素が出力単位だけで構成されるものは、統合画像を作らず整理用コンテナとして扱う。これは `CSP` 上で素材フォルダを束ねるためだけに `_原図/` や `原図/` などを置き、その直下の `_BG/`・`_BOOK/`・アニメーションフォルダだけが実際の必要素材であるケースを想定する。

直下の出力単位：

- CLIP識別・XDTS検出・手動指定・autoProcess のアニメーションフォルダ
- 自動マークの子フォルダ
- 手動で単体出力対象にした子

判定は直下だけを見る。直下に通常レイヤーまたは通常フォルダが混じる場合は、親の自動マークフォルダ自体の統合画像が必要な可能性があるため抑制しない。非表示の直下要素は出力対象外なので判定から除外する。親フォルダの不透明度・合成モードは、CSP上での表示調整に使われる可能性があるため抑制判定には使わない。

この抑制は `autoMarked` 自体を消さず、出力対象・プレビュー対象からだけ親を外す。必要な場合は親フォルダを手動で単体出力マークすることで抑制を上書きできる。

このルールは親フォルダ自身の出力有無だけを決める。アニメセルや他の単体出力へ合成するコンテキストでは、親が `_` 付きかどうかに関係なく、通常フォルダ内のマーク済み独立出力単位（autoMarked、singleMark）を再帰的に除外する。

### 自動アニメ化フォルダ配下のセル命名

通常のアニメーションフォルダ（CLIP識別・XDTS検出・手動指定）では、直下のセル名は連番、連番+セル名、セル名（CSP上のレイヤー名）、連番（シート合わせ）を出力設定で選択できる。初期設定はセル名、アニメーションフォルダ名を付ける、フォルダ名との区切りあり。連番を選んだ場合は最大連番に合わせた1〜4桁になり、4桁固定にもできる。区切りは「なし」にも変更できる。

セル名モードでは、CLIP識別・XDTS検出フォルダに限りアニメーションフォルダ名を付けるか選択できる。セル名が `1` のようにフォルダ名を含まない運用では付加し、`A1` / `A_1` のようにフォルダ名から始まる運用では重複を避けるため省略できる。付加時にも、セル名先頭が「完全なフォルダ名 + 数字」または「完全なフォルダ名 + `_` + 数字」に一致すれば、共通の重複プレフィックスを1回に正規化する。フォルダ名が数字で終わる場合は、`A1` と `A10` のような曖昧な前方一致を避けるため、区切りなしの埋め込み判定は行わない。

一方、自動アニメ化で扱うフォルダ（`_BG`, `_BOOK1` 等）では、**直下のフォルダ名そのものが素材分類の意味情報**（背景／BOOK／セルの役割等）を持つ。

そのため、自動アニメ化されたフォルダ配下では、出力名の設定に関わらず **`_` を取り除いたフォルダ名をセル名として採用** する。例：

```
_BG/
  _e/      ← 工程フォルダ
  BG1      ← 直下の素材フォルダ

→ _ あり（初期設定）: _BG_BG1.jpg / _BG_e.jpg
→ 区切りなし:         _BGBG1.jpg / _BG_e.jpg
```

これにより「どの素材か」「どの工程か」の両方がファイル名に残り、連番化による情報消失を防ぐ。

### 修正工程フチ

`revisionBorderEnabled` は初期状態で有効。工程サフィックスを持つ出力エントリだけに、合成完了後の確認用フチを適用する。本体セル、単体出力、工程サフィックスを持たないエントリには適用しない。

- 画像の内側へ、上辺30px・左右と下辺70pxのフチを工程フォルダリストの `revisionBorderColor` で乗算・不透明度80%合成する。上辺は、印刷・再スキャン時にタップ穴画像へ色がかかりにくい幅に抑える
- 複数の工程サフィックスがある場合は、出力に最も近い工程の色を使う
- 幅140px以下または高さ100px以下なら、四辺の重複塗りを避けるため画像全面を1回だけ塗る
- プレビューと実出力は同じ変換を通し、元の合成キャンバスは変更しない
- フチ色がない旧設定は、既知の工程名・サフィックスに対応する初期色へ補完する

### マーク済みレイヤーの出力

`_` プレフィックスフォルダ（autoMarked）とシングルマーク（手動）は、`collectMarkedLayerContext` で合成コンテキストを収集して出力する。

`collectMarkedLayerContext` はルートから対象レイヤーへのパス上の各レベルで、非マーク・非アニメの兄弟を upper/lower に分類して積む。これにより対象レイヤーの祖先フォルダの外にある層も、PSDのZ順に従って正しく配置される。

通常フォルダの中に別のマーク済み独立出力単位が混在する場合、その独立出力単位だけをコンテキストから取り除き、通常の子が残るフォルダは合成モード・不透明度・マスクを保ったままコンテキストに残す。

### 仮想セットの出力

#### メンタルモデル

仮想セットは **「セルが1つだけの仮想アニメーションフォルダ」** である。
通常のアニメーションフォルダが複数セルを内包し各セルごとに出力するのに対し、仮想セットは常に1ファイルを出力する。

通常のアニメフォルダとの違い：

| 項目 | アニメーションフォルダ | 仮想セット |
|------|-------------------|----------|
| 存在 | PSDツリー上に実在 | UIで定義した仮想構造 |
| セル数 | 複数 | 常に1つ |
| 素材の所在 | フォルダ内に直接含む | PSD内の任意レイヤーを直接参照（コピーでもインスタンスでもない） |
| 合成方式 | セルごとに extractCells | メンバーを非パススルーフォルダとして隔離合成 |
| コンテキスト | 兄弟・祖先から収集 | 同じ除外ルールで insertionLayerId 基準に収集 |
| 出力 | セル数分のファイル | 1ファイル |

#### 合成ルール

メンバーは **非パススルーフォルダと同じ隔離合成** で1枚に合成される（`compositeGroup`）。
メンバー内部のblendModeは隔離合成の中で完結し、外部の兄弟コンテキストには届かない。
合成結果は `blendMode: 'normal', opacity: 100` の単一 FlatLayer として扱われる。

#### コンテキスト除外ルール

`collectVsContextFlats` は `collectLocalSiblingContext` と同じ除外ルールを使う：
- hidden / uiHidden → 除外
- アニメーションフォルダ（＋アニメフォルダ子孫を持つフォルダ）→ 除外
- autoMarked / singleMark → 除外
- 通常フォルダ内の autoMarked / singleMark → 子だけ再帰的に除外し、通常の子が残る親フォルダは残す

#### 処理フロー

`extractVirtualSetEntries` は仮想セットを `OutputEntry` に変換する。

1. `insertionLayerId` を基準に `collectVsContextFlats` で upper/lower コンテキストを収集
2. メンバーレイヤーを `buildMemberFlatsWithOverride` でフラット化
   - 仮想セット固有の visibilityOverrides を適用
   - blendMode/opacity オーバーライドがあるメンバーは1枚に合成してから適用
3. メンバーを `compositeGroup` で非パススルー隔離合成
4. `compositeWithContext` で上下コンテキストと合体して最終合成

## コンテキスト収集の仕組み

各セルの出力はセル単体ではなく、**周辺のレイヤーと合成した完成画像** を生成する。
セルに対して「下に敷く」レイヤーと「上に重ねる」レイヤーを収集する。

```
lower（セルの下に合成）: BG、レイアウト用紙、アニメフォルダより下の兄弟
upper（セルの上に合成）: アニメフォルダより上の兄弟（前景、修正指示等）
```

### 2階層のコンテキスト

```
コンテキスト = globalContext + localSiblingContext

globalContext:
  ルート直下でアニメフォルダでも、アニメ子孫でも、マーク済みでもないレイヤー群
  → 全アニメフォルダ共通で「下」に合成される（BG、レイアウト用紙等）

localSiblingContext:
  アニメフォルダへのパス上の各階層で、パス要素の兄弟を upper/lower に分類
  → アニメフォルダと同階層の兄弟、その親フォルダの兄弟、と外側に向かって積み上げる
```

### コンテキスト除外ルール

以下のレイヤーはコンテキストから除外される：
- アニメーションフォルダ自身（別途処理される）
- アニメーション子孫を持つフォルダ（内部のアニメフォルダが別途処理される）
- マーク済みレイヤー（autoMarked/singleMark。独立出力されるためアニメセルのコンテキストに含めない）

通常フォルダの子孫にマーク済みレイヤーがある場合は、通常フォルダごと捨てずに子だけを再帰的に除外する。たとえば `素材/BOOK/` と `素材/_BG/` が同居している場合、`BOOK/` はコンテキストに残り、`_BG/` は独立出力として除外される。除外後に空になったフォルダはコンテキストに参加しない。

### lower / upper のスタック順

再帰の巻き戻し順（内側 → 外側）でスタックに積まれる。

- **lower**: 外側から描画する（外側BG → 内側コンテキスト → セル）ため **逆順** で flat 化
- **upper**: 内側が最もセルに近いため **そのまま** flat 化

### 合成順序

最終的な合成は `compositeWithContext` で行われる：
```
allFlats = [...lowerContext, ...cellFlats, ...upperContext]
→ compositeStack(allFlats, docWidth, docHeight, background)
```

## プレビューと出力の一致保証

`useOutputPreview` は以下のルーティングで実出力と同一の関数を経由する。
これにより「プレビューと実出力が違う」バグを構造的に防いでいる。

| 選択状態 | プレビュー経路 | 実出力経路 |
|---------|-------------|------------|
| 仮想セット（配置済み） | `extractVirtualSetEntries` | 同一 |
| 仮想セット（未配置） | globalContextで仮プレビュー | 実出力対象外 |
| アニメフォルダ選択 | `extractCells` | 同一（`extractAllEntries` 経由） |
| アニメセル内のレイヤー選択 | `findAnimCellAncestor` → `extractCells` | 同一 |
| マーク済みレイヤー（セル外） | `collectMarkedLayerContext` | 同一（`extractAllEntries` 経由） |

グローバルプレビュー（ナビゲーター中央キャンバス）のみ `flattenToCanvas` を使い、
PSD の生の状態（不透明度そのまま）を表示する。出力とは独立した「現状確認」用。

## 合成モードの対応

### Canvas API でネイティブ対応するモード（16種）

normal, multiply, screen, overlay, darken, lighten, color-dodge, color-burn,
hard-light, soft-light, difference, exclusion, hue, saturation, color, luminosity

pass through はルート合成時に source-over（normal）として扱う。

### 未対応モード（11種、source-over で代替）

dissolve, linear burn, darker color, linear dodge, lighter color,
vivid light, linear light, pin light, hard mix, subtract, divide

UIに警告アイコン（⚠）を表示して作業者に通知する。

### クリッピングマスク

`compositeStack` でクリッピングレイヤーを処理する。
直前の非クリッピングレイヤー（ベース）のアルファ領域で `destination-in` を使って切り抜き、
結果を合成する。ベースがない場合はスキップ。

### レイヤーマスク

ag-psd のマスクCanvasはグレースケール展開済み（R=G=B=マスク値、A=255）のため
`destination-in` は使えず、ピクセル単位でアルファにマスク値（Rチャンネル）を乗算する。

`mask.defaultColor` が 255（白）の場合、マスク範囲外は完全表示。0（黒）の場合は非表示。

## 既知の制限（v1）

| 制限 | 内容 | 優先度 |
|------|------|-------|
| Pass Through フォルダのマスク | 中間合成が必要で未実装。実用頻度が極めて低い | 低 |
| ベクターマスク（`realMask`） | ag-psd は読むが未適用。CSP→PSDでラスタライズされる可能性が高い | 低 |
| 未対応合成モード 11種 | dissolve / linear burn 等を source-over で代替。UIに ⚠ 表示 | 中 |
| 調整レイヤー | ag-psd は読むが効果を適用しない。CSP→PSDで焼き込まれる可能性が高い | 低 |
